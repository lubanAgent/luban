# 快速接入

本指南用“准备资料 → 模型处理 → 保存结果”说明最小接入。对应的可运行离线代码在 [`sdk/example_test.go`](../sdk/example_test.go)，先运行它再替换成自己的业务函数和模型网关。

## 1. 约定一个 Agent

业务启动时读取 JSON 并解码为 `luban.Config`，然后传给 `luban.New`。SDK 本身不扫描目录。以下配置只有一个 `lessonReview` Agent，`flow` 按数组顺序执行：

```json
{
  "lessonReview": {
    "description": "课程评价",
    "flow": [
      { "func": "PrepareReview", "description": "准备资料" },
      { "modelName": "reviewModel", "systemPrompt": "请简要评价课程内容。", "maxLoopCount": 5 },
      { "func": "SaveReview", "description": "保存评价" }
    ]
  }
}
```

`func` 是注册表中的 key，`modelName` 是 `Options.Models` 中的 key；找不到时执行报错。`systemPrompt` 是固定指令。每次执行的用户文本、图片、视频和音频由上一个业务函数返回的 `luban.Request.Messages` 提供，能否处理媒体取决于业务网关。相邻节点按 Go 类型可赋值关系传值，框架不自动把 JSON 字符串转成结构体。

## 2. 接入已有模型网关

业务实现 `luban.ModelInvoker`：

```go
type GatewayModel struct { /* 业务已有的网关客户端 */ }

func (*GatewayModel) Name() string { return "reviewModel" }

func (m *GatewayModel) Invoke(ctx *gin.Context, req luban.ModelRequest) (luban.ModelResponse, error) {
    // 将 req.Messages、req.Tools、req.Temperature 转为网关请求；
    // 把本轮模型正文、ToolCalls 和 FinishReason 转为 ModelResponse。
    // 这里只进行一次网关请求，不能自行执行模型提出的 Tool。
    return luban.ModelResponse{}, nil // 示意：替换成业务网关的真实返回
}
```

这里是**接口形状示意**，其中的空响应不能用于真实任务。实际网关适配包括鉴权、超时、重试与厂商协议转换。可以先运行仓库的 `offlineModel` 示例；正式调用时应检查网关的 Tool Calling 和媒体能力。

## 3. 注册业务函数并运行

业务函数第一个参数必须是 `*gin.Context`，之后最多一个业务输入；最多返回一个业务输出，末尾可选 `error`。例如：

```go
func PrepareReview(ctx *gin.Context, lessonID int64) (luban.Request, error) {
    // 业务在这里读取课程数据，形成动态用户消息。
    return luban.Request{Messages: []luban.Message{{
        Role: luban.RoleUser,
        Content: []luban.Part{{Type: luban.PartText, Text: "请评价这节课。"}},
    }}}, nil
}

func SaveReview(ctx *gin.Context, summary string) (string, error) {
    // 业务在这里负责保存；summary 是上一 Agent 的原始正文。
    return "已保存：" + summary, nil
}

rt, err := luban.New(luban.Options{
    Config: config,
    Models: map[string]luban.ModelInvoker{"reviewModel": gatewayModel},
})
if err != nil { return err }
err = rt.Register(map[string]any{
    "PrepareReview": PrepareReview,
    "SaveReview": SaveReview,
}, nil, nil)
if err != nil { return err }
result, err := rt.Run(ctx, "lessonReview", int64(42))
```

上面最后一段应放在业务初始化和执行入口中，`config`、`gatewayModel`、`ctx` 来自宿主项目，不能作为单个文件直接编译。`Register` 在启动时调用一次；创建和注册成功后再让入口使用 Runtime。没有声明 `Request.Output` 时模型交付原始字符串；需要结构化结论时，在准备函数中设置 `request.Output = luban.Output[YourResult]()`，模型提交内部 OutputTool 后，下一个函数可直接接收 `YourResult`。

## 4. 在已有入口使用

- HTTP：`lubanhttp.Handler(rt, "lessonReview", render)`；业务 `render` 负责现有接口的成功或失败响应。HTTP 入口给首函数传入 `nil`，首函数从 Gin Context 读取和解析请求。
- MQ：`lubanmq.Handler[YourMessage](rt, "lessonReview")` 返回同步回调；首函数接收消息，消费者仍负责 ACK、重试及业务收尾。
- Cron：`lubancron.Job[YourItem](rt, "lessonReview", loader)`；`loader` 返回本次待处理项，每项单独执行一次 Agent。

如果需要业务 Tool，定义实现 `Name/Description/Input/Invoke(*gin.Context, any)` 的类型，经 `Register` 注册，再在 Agent 节点的 `tools` 列表中写名称。Skill 用 `luban.Skill{Name, Description, Content}` 注册，节点用 `skills` 列表引用；需要运行时获取正文时可提供 `SkillBackend`。工具调用是否继续由模型与框架循环决定，业务自己负责副作用和幂等。

`Run` 是同步调用，正常返回最后一个实际节点的业务输出；失败返回 `nil, error`。流程只有顺序节点，不支持配置分支和跨请求恢复。如果 HTTP 请求可能超时，可由业务使用 MQ/Cron 在另一次入口启动适当的任务；`RunFrom` 仅从指定的唯一业务函数节点开始执行，不会恢复旧 Run 的内存状态。

## 5. 查看执行过程

按需给 `Options.TraceWriter` 传入业务日志写入器，保存每个完整 `TraceEvent` 为一行 JSON；同一次 Run 用 `luban.RunID(ctx)` 关联。将授权的本地日志导入 [Trace 查看页](../sdk/trace-viewer/index.html)；不需要额外服务，也不要把含用户内容的日志上传到公共网站。完整的接口代码与行为测试以 SDK 源码为准。
