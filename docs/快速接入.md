# 快速接入

这份指南从仓库根目录的 Luban 服务开始。最简单的 Agent 只需要一份配置；当流程需要业务数据或领域规则时，再加 Go 函数、Tool 或 Skill。

## 1. 运行现成 Agent

`conf/luban.yaml` 统一配置模型地址和 Key；`agents/summary/agent.json` 的 `modelName` 填网关支持的真实名称。

```sh
export LUBAN_OPENPROXY_BASE_URL="https://your-gateway/openproxy/rp/v1"
export LUBAN_OPENPROXY_KEY="your-key"
go run . run summary --input '{"userPrompt":"总结今天的会议。"}'
```

CLI 不需要 IPS 或业务数据库，最终结果写 stdout；普通日志和 Trace 统一走公司 zlog，默认本地写入 `log/luban.log`，搜索 `luban_trace` 或 `runId` 即可收集。`conf/mount/resource.yaml` 默认 `mysql: {}`，不会初始化志愿填报库。

HTTP 模式先填写 `conf/mount/custom.yaml` 的公司 IPS 配置并登录，然后 `go run .`：

```sh
curl -X POST http://localhost:8080/luban/ai/agent/summary \
  -H 'Content-Type: application/json' \
  -H 'Cookie: <公司登录会话>' \
  -d '{"userPrompt":"讨论结论：先完成迁移，然后联调。"}'
```

帮助和错误命令不加载资源；CLI 不启动监听或后台 Worker。公司 HTTP 登录规则保持生效。

## 2. 写一份 Agent 配置

创建 `agents/<agentKey>/agent.json`。`flow` 是按顺序执行的节点数组；纯模型 Agent 只需一个 Agent 节点：

```json
{
  "flow": [
    {
      "modelName": "deepseek-chat",
      "systemPrompt": "用简洁的中文总结内容，保留结论和待办。",
      "temperature": 0.2,
      "maxLoopCount": 5
    }
  ]
}
```

默认 HTTP 地址为 `POST /luban/ai/agent/<agentKey>`。模型是首节点时，入口简写会被转换成一次用户消息：

```json
{"userPrompt":"请概括这段内容。"}
```

图片和视频使用 URL 数组：

```json
{"userPrompt":"分析这段材料。","images":["https://example.com/page.png"]}
```

```json
{"userPrompt":"总结这段视频。","videos":["https://example.com/clip.mp4"]}
```

需要多轮历史、音频或精确控制消息结构时传 `messages`；`messages` 与 `userPrompt/images/videos` 不能混用。媒体能否处理取决于所用模型和网关。

## 3. 配置模型连接

连接按服务项目归组。每个项目可以有一个默认连接，也可以用非空 `modelList` 给特定模型指定网关：

```yaml
llm:
  admissions:
    - baseUrl: https://openproxy-cn.yukework.com/openproxy/rp/v1
      apiKey: ${LUBAN_OPENPROXY_KEY}
    - modelList: [claude-sonnet]
      protocol: anthropic
      baseUrl: ${CLAUDE_BASE_URL}
      apiKey: ${CLAUDE_API_KEY}
```

先精确匹配 `modelList`；未匹配时使用该项目的默认连接。模型名必须写网关接受的真实名称，不带别名前缀。只有一个项目时 Agent 可省略 `projectKey`；有多个项目时需在 Agent 配置根部指定项目 Key。

## 4. 需要业务逻辑时，再登记函数或 Tool

当 Agent 需要读取业务数据、做领域计算或保存结果时，把流程拆为业务节点和 Agent 节点：

```json
{
  "flow": [
    {"func": "PrepareCall"},
    {
      "modelName": "deepseek-chat",
      "systemPrompt": "根据通话文本生成摘要。"
    },
    {"func": "BuildResult"}
  ]
}
```

`PrepareCall` 返回 `luban.Request`，通过 `Request.Messages` 提供本次用户文本；Agent 节点返回模型文本；`BuildResult` 接收上一步的字符串并组成业务结果。

业务函数放在 Agent 包中并显式登记：

```go
func init() {
    luban.RegisterFuncs(PrepareCall, BuildResult)
    luban.RegisterTools(QueryCourse{}, SaveSummary{})
}
```

含 Go 函数或 Tool 的 Agent 包由 `agents/imports.go` 导入；纯 JSON Agent 自动加载，无需改 Go。删除带 Go 的 Agent 时也应移除其 import。框架在启动时校验登记的名称和配置引用。函数必须以 `*gin.Context` 开头，最多接收一个业务输入、返回一个业务输出，末尾可选 `error`。类型按 Go 可赋值关系传递，不会自动把任意 JSON 字符串转成下游结构体。

Tool 实现 Luban 的 Tool 接口，工具名、说明、输入类型和调用方法固定；配置中列入 `tools` 后才对该 Agent 可用。Agent 决定是否、何时、调用几个 Tool。Tool 的外部副作用、权限和幂等由业务负责。

模型需要提交 Go 结构体时，准备函数在 Request 中声明 `Output: luban.Output[Result]()`；不声明则返回模型原始文本。Skill 放在 Agent 的 `skills/<name>/SKILL.md`，并在 Agent 配置里按名称引用。

## 5. 数据库、HTTP 与公共代码

通用业务查询和外部接口可由多个 Agent 复用：

- Gorm 表结构和数据库访问放根目录 `models/`，连接配置放 `conf/` 或由宿主注入。
- 公司模型 HTTP 放 `adapters/`，协议转换复用 SDK；业务外部 API 放自己的 `agents/<agentKey>/`，不再保留根 `api/`。
- Agent 的领域规则、配置、节点衔接、Tool 登记和 Skill 放 `agents/<agentKey>/`，按需建子包。
- 通用 HTTP 入口由 `router/` 接收，监听和配置加载由 `server/` 管理。

数据库通过服务配置或宿主注入。纯模型 Agent 不需要数据库。SDK 不会自动创建业务表或迁移数据。

## 6. 志愿填报迁移案例

`agents/admissions/` 展示一份 Agent 配置、两个业务节点、四个 Tool 和六份 Skill 的迁移形态。XXSY 入口通过 `router.RegisterSubmission` 使用 SDK 的 `lubanhttp.SubmitHandler`：SDK 解析 HTTP 请求，`agents/admissions/submit.go` 判断消息/确认并调用业务仓库写任务，立即返回 conversationId、taskId 与状态；`agents/admissions/worker/` 后台领取任务，再让 SDK 执行这一套 Agent 配置。领域规则在 `agents/admissions/strategy/`，数据库访问在 `models/strategyrepo/`；消息历史、草稿、检查凭据和任务租约由业务代码维护。异步结果查询/推送与发布接口不在当前范围，Luban 不做跨 Run 恢复。

默认不启动该业务。启用时，在公司 `conf/mount/resource.yaml` 配置 `mysql.admissions`（或通过 `Options.Databases` 注入），在 `conf/luban.yaml` 设置 `backgroundAgents: [admissions]`，并提供符合当前 Gorm Model 的 admissions 数据库。`http.excludeAgents: [admissions]` 始终阻止其自动同步 HTTP；Worker 启用也会排除对应同步路由。CLI 的 summary/callsummary 可直接执行，admissions 只能通过受信任 Worker 执行，不能用 CLI 伪造领取任务。当前目标数据库 DDL 尚未与实际库核验，所以该目录是迁移开发案例，不是可直接接生产库的迁移包。

## 7. 验证与查看 Trace

```sh
go test ./...
go vet ./...
make check
```

每次 Run 都会生成 `runId` 并输出结构化 Trace 日志。用 `runId` 收集完整事件后，可在本地打开 [Trace 查看页](../sdk/trace-viewer/index.html)。日志含用户内容、模型请求上下文、Tool 参数或 Skill 正文时，应按业务日志规范控制访问权限。

更多源码入口见仓库 [README](../README.md) 和 [开发进度](开发进度.md)。
